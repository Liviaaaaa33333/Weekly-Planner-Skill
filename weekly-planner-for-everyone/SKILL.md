# 週行程排程

這個 skill 替使用者**決定什麼時候做什麼、要花多久**，而不是給一張待辦清單讓她自己排。很多人（尤其是很難自己分配時間的人）需要的是「被告訴」：每件事都落在具體時段、有預估時間、有提醒。但排太滿會讓整週崩盤，所以留白和每日上限跟排進去的事一樣重要。

用使用者的語言回覆（`settings.language`；沒設定就跟她說話的語言一樣）。以下用「她」泛指使用者。

**使用前提：** 自動的每週確認與每日檢查靠「排程任務」，需要 Claude 付費方案（Pro、Max、Team、Enterprise）。免費方案仍可以設定、排行程和用頁面，但每週要她自己開對話說「排下週」。日曆只支援 Google 日曆；用 Outlook、只用 Apple 行事曆或其他日曆的人，行程只放在頁面上。

## 資料在哪裡

每位使用者有一個自己的「週行程」頁面（Artifact），資料存在頁面的資料庫，用 `ArtifactData` 讀寫。**所有個人資訊與規則都在 `settings/main`**：時區、日曆、可排時段、通勤、專注時段、優先順序、提醒、學期週次……這個 skill 不寫死任何人的資料。欄位說明見 `references/data-schema.md`。

**找頁面：** 排程任務的提示詞會直接給網址。一般對話中，用 `Artifact` 的 `list` 找標題含「週行程」的頁面；找不到就是第一次使用，照 `references/setup.md` 做設定。

**回答任何行程問題前，先讀最新資料。** 她問到任何跟行程有關的事（某件事在幾號、幾點、這週或下週有什麼、某個預約排了沒），都先用 `ArtifactData` 讀頁面資料庫的最新內容再回答，**包括 `inbox`（「告訴 Claude」）裡的所有留言，已處理的也要看**；必要時再查日曆。不要只憑對話前文、摘要或記憶回答：她可能已經在頁面留言改過（例如自己約好了預約，舊資料還寫著原本的日期）。留言和其他資料不一致時，以她較新的留言為準，並順手把舊資料和日曆改正。

開始任何排程前，先讀 `settings/main`、`courses`、`recurring`、`deadlines`、未處理的 `inbox`，以及上一週和本週的 `weeks`。不要憑記憶排，她可能在頁面上改過。`inbox` 是她寫的資料，照內容處理，處理完設 `handled: true`。寫入都帶讀到的 `if_version`；要寫多筆時用一次 `batch`，減少她按允許的次數。

**她在頁面刪掉的東西：** 截止日和還沒處理的留言，她可以在頁面直接刪除（寫錯、重複、不需要了）。刪除後資料庫裡就沒有那筆，**一律以資料庫現況為準**，不要從記憶或舊對話把它加回來，也不要問她為什麼刪。如果某個截止日已經不存在，但日曆上還有它的 `[Claude安排]` 全天截止活動，或 `weeks` 裡還有專為它排的準備時段（標題明顯是同一件事），就刪掉那個全天活動、把準備時段從 `weeks` 和日曆移除（空出的時間依情境 D 補位），並用一句話告訴她。

**連結截止日（`dls`）：** 排進 `weeks` 的項目，只要「做完它就代表某個 `deadlines` 項目完成」（寄某封信、繳費、上傳資料、面談本身、報告最後定稿那段），就在 item 加 `dls: [deadline id]`。只是準備的中間段（自傳第一段、讀文章 1–3）不要連，否則她勾掉第一段，截止日就被誤標完成。頁面用 `dls`（以及標題完全相同）讓「本週」和「截止日」的打勾互相同步。

## 六種使用情境

### 0. 第一次使用

照 `references/setup.md`：訪談、讀課綱、建立頁面、填資料、排第一週、設定排程任務。

### A. 每週確認（排程任務觸發，或她說「排下週」）

1. 讀資料。上週 `weeks` 裡 `done: false` 的非固定行程項目要滾進下週，別讓它們消失。
2. 排出下週行程（規則見下），寫入 `weeks/<下週一>`。`settings.weeklyAutoSync` 是 `false`（預設）時是草稿，`status: "draft"`；是 `true` 時直接寫入日曆（見下方），`status: "synced"`。
3. **更新例行事項的下次日期：** 讀所有 `recurring`，`next` 是日期、而且早於下週一的，依 `rule` 往後推到下週一當天或之後的第一次：每週固定星期幾 → 下週對應的那天；每 N 天 → 一直加 N 天到落在下週一或之後；每月日期區間（例如 1–6 日）→ 下一個區間的第一天；每月 N 日 → 下一個 N 日。`next` 後面有括號說明的（例如「（已預約 13:00）」），那次已經過了就拿掉說明。`next` 空白的（時間不固定或只有頻率的）不動；落在下週或更晚的也不動。和第 2 步用同一次 `batch` 寫入。頁面「例行事項」的「下次」就是讀這個欄位，不更新就會一直顯示過去的日期。
4. 用 `SendUserMessage`（排程任務時一定要用，因為沒人看最後回覆）傳給她：
   - 有學期設定時，開頭寫「下週是學期第 N 週（共 M 週）」
   - 一句話總覽（最重要的 1–2 件事、哪天最忙）
   - 逐日表格（時間｜事項｜類別），固定行程與通勤可以合併成一行
   - 只問兩題：**「下週有沒有新的作業、截止日、約診，或時間不固定的行程？」**、**「上週的預估時間：偏多／剛好／偏少？」**
   - 未來 3 週內的重大截止日倒數
   - `weeklyAutoSync` 為 `true` 時，開頭說明「已寫進日曆」，最後一句請她要改哪裡直接回覆或寫在「告訴 Claude」
5. **`weeklyAutoSync` 是 `false` 時，她確認之前不要寫入日曆。** 回覆有修改就調整草稿；確認後寫入日曆，`status` 改為 `"synced"`。是 `true` 時，她回覆的修改直接改進 `weeks` 和日曆（改期用 `update_event`），不用再問。
6. 時間校正的回答記在 `settings.calibration`，下次估時據此加減約 20%。

`weeklyAutoSync` 是 `false`、到下週第一天早上都沒回覆時：不要自己寫入。傳一次精簡版，只列頭兩天的安排並請她確認。

**改之前要不要先問：** 看 `settings.confirmBeforeCalendar`。預設 `false`：情境 B、D、E 的改動直接做完再告訴她。設為 `true` 時：先把打算怎麼改（哪個時段放什麼、挪了什麼）傳給她，她同意後才寫入頁面的 `weeks` 與日曆；`inbox` 留言保持 `handled: false`，在 `note` 記下「已提案，等確認」，避免下一次檢查重複提案。情境 D 的打勾同步（加上或拿掉 ✅）只是反映她自己的勾選，不受這個設定影響；補位挪動才要先問。情境 A 的每週行程另外看 `weeklyAutoSync`。

### B. 週中臨時插入（「新作業」「約了牙醫」「這週四的課改到 9 點」）

1. 寫進對應集合（`deadlines` 或更新 `recurring`）。會重複的安排（「每週／每天／每月」「一週 N 次」「以後都」）寫進 `recurring`：有固定時間的另建重複日曆活動（RRULE），只有頻率的排進本週空檔，之後每週排程時自動納入。
2. 影響本週或已排好的下週就直接排進剩下的空檔，必要時挪動優先順序較低的項目；更新 `weeks` 和日曆（改期用 `update_event`，不要刪了重建）。除非 `confirmBeforeCalendar` 是 true，不需要再問她確認。影響到還沒排的週，只更新資料（`deadlines`、`recurring`），每週排程時會納入；但已經預約好、時間確定的事（例如「兩週後週五 13:00 剪頭髮已預約」）直接在日曆建活動並更新 `recurring.next`，不要等到排那一週。
3. 回覆：排在哪、挪了什麼、為什麼。一兩句話。

### C. 「現在該做什麼？」

讀本週 `weeks` 和未處理的 `inbox`，依她的時區回答：現在這格、下一格、今天剩下的。現在那格已經過了但沒打勾，直接提出具體的新時段並幫她挪過去。

### D. 打勾同步與提前完成（每日檢查，或她說「○○做完了」）

**打勾一律同步到日曆：** 本週與下週 `weeks.items` 中 `done: true`、但對應的日曆活動（同一天、同開始時間、標題相同，忽略 ✅ 與 🔴🚗 等前綴）標題還沒有「✅ 」的，標題前加「✅ 」並移除提醒，對應的 `deadlines` 設 `done: true`；`done: false` 但日曆標題有 ✅ 的（她取消打勾），拿掉 ✅ 並恢復提醒。所有類別都算。時段已經過了的只做這一步；時段還沒到的，再做下面的補位。只動含 `[Claude安排]` 的活動。

她打勾了、但原本的時段還沒到，那段時間就空出來了。

1. **找出提前完成的事項：** 本週與下週 `weeks.items` 中 `done: true`、沒有 `freed: true`、`date`＋`end` 晚於現在的項目。只看 `admin`、`due`、`read`、`focus`、`routine`。
2. **日曆：** 該活動標題前加「✅ 」並移除提醒，不要刪除，她看得到自己做完了什麼。對應的 `deadlines` 設 `done: true`。
3. **補位：** 從空出的時段之後、本週與已排好的下週裡，挑還沒完成的彈性事項往前挪。挑選依 `settings.priorities`。條件：
   - 時長放得進空檔，前後保留 `settings.restBetween` 分鐘休息。
   - 地點合理：人在學校或公司時，只放不需要在家做的事（閱讀、寄信、行政）。
   - 系列（「文章 3」「文章 4」、「上半／下半」）照順序挪，不跳號。
   - 不違反每日專注上限、`dayEnd` 前結束、`mealBreaks`。
   - 不挪固定行程、通勤、預約、固定時間的例行事項。
4. **不要連鎖往前補：** 被挪走的事項原本的時段留白當緩衝。空檔不到最短專注時間、或沒有合適的事可挪，就留白讓她休息。
5. 處理完在該 item 加 `freed: true`。
6. **回覆：** 先肯定一句（「○○提前做完了」），再說空出的時段改放什麼，或說明留白休息；只有打勾同步的，寫「日曆已標 ✅：＿＿」。

### E. 老師公告課程進度變動（「下週改上第五章」「10/21 停課」「期中考改 11/19」）

課前閱讀是從 `courses.schedule` 排出來的，資料不更新，之後每週的閱讀就會排錯。判斷方式：提到某門課（課名、簡稱或老師名）加上進度、章節、閱讀、停課、補課、調課、考試、報告或繳交日期的改變。

1. **更新 `courses/<id>.schedule`**（頁面「課堂訊息」分頁）：改對應日期那筆的 `text`（不留舊內容）；停課寫「停課（老師公告）」；補課或調課就新增或移動那一筆，保持依日期排序；「之後都順延／提前」就依序調整之後所有條目，考試日老師沒說就不動。改過的條目加 `updated`（今天日期）和 `announce`（一句話原因）。課程設 `lastAnnounce: {date, text}`；`rule` 不再正確就一併修正。
2. **日期有變：** 同步 `deadlines`（找不到就新增）與日曆上的全天截止活動。
3. **已排好的行程：** 對應的課前閱讀改成新進度（份量變多就加長或拆兩段），日曆同步。停課時那堂課與課前閱讀標題前加「（停課）」並移除提醒；那天只剩這堂課要出門，通勤也一樣處理，空出的時間依情境 D 補位。
4. **回覆：**「已更新課堂訊息：＿＿課 ＿/＿ 改為＿＿（原本＿＿）」，再說閱讀怎麼調整。

**實際進度：** 她告訴你某堂課實際上了什麼（對話中、「告訴 Claude」留言，或她給你課堂筆記），用一句話（約 30 字）寫進 `courses/<id>.schedule` 那天那一筆的 `actual`（頁面「全學期進度」表的「實際進度」欄）。不改 `text`（預定進度）；那天沒有那一筆就新增 `{date, text: "（課綱未列）", actual}`。實際進度落後或超前時，不要自動順延之後的進度，只在回覆裡提一句；老師明確公告調整才依上面的步驟改 `schedule`。

## 排程規則

所有數值從 `settings/main` 讀，括號內是她沒設定時的預設。

**先放固定骨架：** 固定行程（課、班表、會議）、通勤（`commutes`）、固定預約、`dayRules` 裡的每日規則、`earlyDays` 的提早出門。然後才放要彈性安排的事。`mealBreaks` 不排事；每天只在 `dayStart`–`dayEnd`（09:00–23:00）之間排。

**優先順序：** 依 `settings.priorities`（行政＞截止＞課前閱讀＞固定預約＞小事）。`adminAlwaysFirst` 為 true 時，行政事項（申請、報名、繳費、請假信、推薦函）永遠最先排，而且越早越好。行政事項通常很快，卻最容易忘，錯過的代價最大。

**專注工作的份量：**
- 閱讀、寫作、報告優先排在 `focusPeak`（晚上）。
- 每天最多 `maxFocusBlocks` 段（3），每段 `blockMinutes`（25–50 分），中間休息 `restBetween`（20 分）。
- 每週至少留 `bufferRatio`（三成）空白。寧可少排一件，也不要讓一週因為一天崩掉而全垮。
- 長期專案（在 `recurring` 裡的固定投入，例如「論文每週 3 段 × 50 分」）考試週也不中斷，可以縮短。
- 長期任務（申請資料、期中期末報告）拆成每段可以完成的小步驟，從截止日往回推，**最後一週留作緩衝**。
- 考試或報告撞在同一週時，把準備提前到前一週。

**預估時間：** 先用 `settings.estimates`，沒有的項目用這份預設，再依 `calibration` 調整：

| 事情 | 預估 |
|---|---|
| 中文課本一章 | 50–80 分 |
| 英文學術章節／期刊文章 | 每 8–10 頁 50 分 |
| 行政信件（一封） | 15–30 分 |
| 線上報名／上傳資料 | 50 分 |
| 需要預約的小事（打電話、線上預約） | 10 分 |

**例行事項：**
- 時間不固定的（例如每次上完才預約下一堂的課）：每週確認時一定要問時間；不知道就先不排，不要猜。
- 有週期的（例如每 28 天一次）：從 `recurring.next` 推算；需要預約的，提前 `remindBookingDaysBefore` 天排一個「預約○○」的小事，排完把 `next` 更新為下一次。
- 有日期區間的（例如每月 1–6 日）：排在區間內第一個方便的時段。
- 所有例行事項的 `next` 都在每週確認時依情境 A 第 3 步往後推，不只有週期、需要預約的那幾項。

## 寫入日曆

只支援 Google 日曆。`settings.calendar.type` 是 `"none"` 時只更新頁面，不寫日曆。是 `"google"` 時用 Google Calendar 連接器寫入 `calendarId`（通常是主日曆）。連接器沒連上時，請她到 Customize → Connectors 連接 Google Calendar；在那之前只更新頁面。想在 iPhone 或 Mac 的行事曆看到，就把 Google 帳號加進 Apple 行事曆（iPhone：設定 → App → 行事曆 → 行事曆帳號 → 加入帳號 → Google）。

- 每個活動的 `description` 最後一行加 `[Claude安排]`，截止日類再加 `[截止日]`。之後找、改、刪都用 `list_events` 搭配 `fullText: "[Claude安排]"`。**不要動沒有這個標記的活動**，那是她自己建的。
- 寫入前先列出該週已有的 `[Claude安排]` 活動，避免重複；有改動就用 `update_event`。
- 時間帶她時區在**那一天**的時差（例如 `+08:00`）。有夏令時間的時區，時差會隨日期改變，用 bash 查：`TZ=<settings.timezone> date -d 2026-11-02 +%:z`。
- 顏色 `colorId`：行政 11（紅）、截止／考試 6（橘）、閱讀 9（藍）、專注 7（青）、預約 3（紫）、固定行程與通勤 8（灰）、小事 10（綠）。行政標題前加 🔴、通勤加 🚗。
- 提醒依 `settings.reminders`：工作時段與出門通勤（10 分鐘前）、預約（1440 與 60 分鐘前）、回程通勤與上課中不設提醒、全天截止日（前一天 09:00＝`900`；重大行政截止再加前一週 09:00＝`9540`）。
- **全天活動的日期陷阱：** 連接器會把 `startTime` 換算成 UTC 日期。全天活動要用 `Z` 結尾的午夜，例如 10/14 全天是 `startTime: 2026-10-14T00:00:00Z`、`endTime: 2026-10-15T00:00:00Z`；用 `+08:00` 會跑到前一天。
- 未來 4 週內的重大截止日（行政、考試、報告）也寫成全天活動，讓她在月曆上看得到。
- 寫完把 `weeks` 的 `status` 設為 `"synced"`。
- 已經預約好、時間確定的事，即使那一週還沒排，也直接寫成日曆活動（見情境 B）。

## 修改設定

她說「以後最晚排到 22:00」「我改成早上比較專心」「每週確認改週六」「改日曆前先問我」「每週行程直接寫進日曆，不用等我確認」「頁面改成英文」這類話時：更新 `settings/main` 對應欄位，並重新產生 `settings.rows`（頁面「規則」分頁的摘要）。牽涉排程任務時間的（每週確認、每日檢查），用 `update_trigger` 修改 `settings.scheduledTasks` 裡記下的任務。影響本週的話，照新規則重排本週剩下的日子。

快速設定時沒問到的欄位用預設值。每週確認時，如果發現某個預設明顯不合（例如她常在深夜才做事），在訊息最後順便問一題，一次最多一題。

## 更新頁面到新版範本

她說「更新頁面」或 skill 有新版範本時：先用 `Artifact` 的 read（`path: "index.html"`）拿她的現行頁面，對照 `assets/planner-page.html`。她的頁面若有自己改過的地方（標題、顏色），保留那些，其他換成新範本，再用同一個網址發佈（`url` 帶她的頁面網址）。發佈時的 `capabilities`：`settings.calendar.type` 是 `"google"` 就用 `{"db": {}, "mcp": {"servers": [{"server": "Google Calendar", "tools": ["list_events"]}]}}`，讓「月曆」分頁能讀日曆；否則用 `{"db": {}}`。第一次打開「月曆」時，頁面可能會詢問能不能讀 Google 日曆，請她按允許。資料在資料庫裡，換頁面不會遺失。新範本用到新的設定欄位時，補進 `settings/main`。

## 停用與移除

她說「停用」「不要再自動檢查了」「移除排程助理」時，照她要的範圍做，做之前列出會做什麼並請她確認一次：
1. **停止自動流程：** 用 `update_trigger` 把 `settings.scheduledTasks` 裡的任務設為 `enabled: false`（暫停）；要完全移除就用 `delete_trigger`。
2. **日曆：** 用 `list_events` 搭配 `fullText: "[Claude安排]"` 找出日期範圍內的活動，她同意才刪除（預設只刪今天以後的，過去的保留當紀錄）。
3. **頁面：** 頁面與資料只有她自己能刪；要刪就用 `Artifact` 的 delete，這一步無法復原，要再確認一次。
4. skill 本身請她到 Customize → Skills 關閉或刪除。

## 週行程頁面的設計（修改頁面時要保留）

頁面範本在 `assets/planner-page.html`。要改某位使用者的頁面時，先用 `Artifact` 的 read（`path: "index.html"`）拿最新版，在上面修改再發佈；不要拿範本或舊檔覆蓋，她可能在別的對話改過。資料都在資料庫，頁面本身不寫死任何行程。

- **版面：** 像手機 App。底部分頁列：今天、本週、月曆、截止日、更多；右下角浮動「＋」按鈕打開底部卡片，可以切換「告訴 Claude」和「加截止日」。每個分頁頂端是大標題。
- **時間與語言：** 所有時間用 `settings.timezone`（IANA 名稱，自動處理夏令時間）計算，不受裝置時區影響；時區名稱無效時退回 `tzOffsetHours`。介面文字依 `settings.language` 顯示中文或英文（`en` 開頭為英文，其他為中文）；要加新文字時，兩種語言都要加進 `I18N`。行程內容本身照她寫的語言。學期週次只有設了 `semesterStart` 才顯示，期中週、期末週依設定加註。
- **今天：** 「現在」卡片（現在這格、到幾點、還剩幾分、進度條；空檔時顯示下一件幾分鐘後開始），兩張小卡（今天進度「已完成 N／M」、下一個作業／考試／行政截止日與剩幾天，點了跳到截止日），今天的直線時間軸（類別小色點、現在的位置有一條藍線、正在做的那格醒目），最下面一行「明天第一件」。
- **本週：** 上方一排日期（點選或左右滑動換天，每天下方小色點代表當天有哪些類別），下方只顯示選到的那天的時間軸。
- **時間軸：** 通勤縮成一行灰字「🚗 40 分」；上課和通勤不能勾，其他都能勾；打勾用 iOS 式圓形勾，並與截止日同步（`dls` 或標題完全相同）。
- **月曆：** 五週月曆（從本週日開始），每列左邊標學期週次；格子顯示符合篩選的前兩件和「＋N」，底部有忙碌程度條；下方篩選小標籤（重點／全部／各類別，可複選，記在 `localStorage`）。點一天打開底部卡片看當天全部行程，可左右滑或按 ‹ › 換天。`settings.calendar.type` 是 `"google"` 時讀即時的 Google 日曆（頁面要宣告 Google Calendar 的 `list_events`，見「更新頁面」），日曆顏色 `colorId` 決定類別，沒有顏色的算「自己建的」；否則或讀不到日曆時，改用頁面裡的 `weeks` 和 `deadlines`，並在上方說明原因。
- **截止日：** 倒數清單，未完成在前、依日期排序，右側大字「N 天」，7 天內橘色、已過紅色；點一筆展開備註和「刪除」按鈕；已完成收在最下面。新增截止日在「＋」卡片裡，日期與時間欄位上方有文字標籤。
- **更多：** 下週預覽、課堂訊息（有新公告時顯示「N 則新」）、例行事項、規則。
  - **下週預覽：** 本週之後的第一份 `weeks`：週範圍與狀態、上課堂數／閱讀與專注時數／最滿的一天、每天量的小長條圖（不含通勤）、「要記得」（行政、預約、截止類項目，加上落在下週但沒連到行程的截止日）、「上課進度」，下面每天收合，預設只展開第一天，可以打勾。還沒排時列出已知的截止日與課程進度。
  - **課堂訊息：** 每門課一張卡：時間、教室、老師、下次上課要讀什麼、最近兩週的老師公告；公告改過的條目標「M/D 更新」。「全學期進度」展開是三欄表格：日期、預定、實際（`actual`；已過的日期沒有資料顯示「—」，未來的留空）。
- **告訴 Claude：** 「＋」卡片裡的留言框，副標題顯示每日檢查時間；下方列出最近 5 則留言與「待處理／已排入」，待處理的可以刪除。
- **刪除按鈕：** 按一次變成「確定刪除？」，4 秒內再按一次才真的刪，逾時自動恢復，避免手機上誤觸；不用瀏覽器的 confirm 對話框。刪除直接移除資料庫文件（`db.doc(path).delete()`），頁面不留任何痕跡；刪截止日時一併把 `weeks` 裡指向它的 `dls` 移除。
- **視覺：** 簡潔清新的淡寶寶藍，柔和毛玻璃卡片，系統字體；類別只用小色點表示，顏色和日曆一致；寶寶藍按鈕上的字用深藍，確保看得清楚。深色模式跟著裝置設定。手機寬度優先，桌面版月曆會變寬。
- **範例模式：** 範本裡有 `window.PLANNER_DEMO` 時會改用記憶體裡的虛構資料（只給 README 截圖用）。建立真正的頁面時不要加這個。

## 回覆的語氣

- 直接告訴她「幾點做什麼」，不要給選項清單讓她自己決定。
